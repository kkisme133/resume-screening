# 评分规则与字段定义

Step 3（结构化提取）和 Step 5（打分）使用。

## 一、结构化提取字段

每份简历抽成下面的字段。**只抄事实，不做判断**；抓不到就写"简历未体现"。

| 字段 | 说明 | 用途 |
|---|---|---|
| 姓名 | | 标识 |
| 学校 / 学历 / 专业 / 年级 / 预计毕业时间 | | 门槛判断 |
| 在读状态 | 在校生 / 已毕业 / 未体现 | 门槛判断 |
| 联系方式 | 邮箱、电话（**不参与评分**） | 联系 |
| 实习经历 | 公司、岗位、起止时间、内容、成果 | 门槛 + 打分 |
| 项目经历 | 项目名、角色、时间、内容、成果 | 打分 |
| 学生工作 / 社团经历 | 组织、角色、时间、成果 | 加分项 |
| 技能 / 证书 | 工具、语言、证书及熟练度表述 | 门槛 + 打分 |
| 可实习时间 | 每周天数、持续月数、可到岗日期 | 门槛判断 |
| 期望地点 | | 门槛判断 |

**时间线字段（起止时间）必须完整提取**，这是判断"时间线自相矛盾"和"短期跳换"的基础。

## 二、门槛判断规则

### 门槛只能建立在"结构性内容"上

这是全篇最重要的一条原则。简历里的信息分两种：

| 类型 | 内容 | 能不能当门槛 |
|---|---|---|
| **结构性内容** | 教育背景、实习/项目经历、起止时间、证书 | **可以**。"不写"这个判断可靠——这些是简历的骨架，不写等于没内容 |
| **可选内容** | 技能栏、自我评价、期望地点、到岗时间 | **不可以**。写不写取决于个人习惯，"没写"说明不了任何问题 |

### 四层分类

| 层级 | 内容 | 处理 |
|---|---|---|
| **门槛** | ① 资质：学历、在读状态、毕业年份、专业<br>② 证书：JD 明确要求且有客观判定标准的<br>③ 经历：JD 明确写"必须有"的 | 不满足即淘汰 |
| **雷区** | 时间线自相矛盾、近 1 年 ≥3 段短期经历、关键信息严重缺失 | 命中即淘汰 |
| **平台筛选条件** | 到岗时间、实习时长、每周天数、期望城市、薪资期望 | 不作简历判断，平台侧筛或面试确认 |
| **加分项** | 技能、JD 未写"必须"的相关经历、专业优先、学生工作等 | 按证据强弱加分 |

### 技能一律不作门槛

技能的判断依据是"水平"，而技能信息属于**可选内容**。证据在两个方向上都不可靠：

- **写了不代表会**：越会包装的人越爱写"精通"
- **没写也不代表不会**：很多人能力强，但不爱在简历上写

所以技能只在"岗位硬技能匹配"维度按证据强弱加分（有项目/成果 > 只列在技能栏 > 完全没提），没写不扣分，并列入面试验证清单。

> **唯一例外：证书。** 证书有编号和分数，非黑即白，而且没人会故意不写——所以它可以当门槛，前提是 JD 明确要求、且证书有客观判定标准（考试通过 / 发证机构认证），而不是"熟练""精通"这类水平描述。

### 经历作门槛的条件

经历是结构性内容，判断可靠，但**只有 JD 原文出现"必须 / 要求 / 需具备"这类措辞时才能设为门槛**。
JD 写"有…优先 / 为佳"，或者完全没提 → 相关经历进**加分项**，按证据强弱加分，不淘汰任何人。

### 为什么门槛要设得这么窄

门槛设错的代价是**漏人**，而且是**不可见的漏**——你永远不会知道被淘汰的那批人里有没有好的。
降成加分项之后，人还留在表里，只是排在后面，你还看得见、还能回头捞。

> 早期版本踩过的两个坑：
> 1. 把到岗时间、实习时长当"默认门槛"——用真实简历试跑时，一份排名前 3%、拿过两次国家奖学金的简历被卡在"待定"，原因只是她没在简历里写"能实习 3 个月"。问题不在候选人，在规则。
> 2. 把"有 Python 项目经验"这类技能要求放进门槛——技能信息在简历里是可选内容，写不写取决于习惯，用它淘汰人容易误伤。

判定结果三选一：

- **通过**：所有 L1 门槛项都满足，且未命中雷区
- **待定**：L1 门槛在简历中缺少判断依据（例如没写学历、没写毕业年份）→ 必须附一条"待确认问题"
- **淘汰**：违反 L1 门槛或命中雷区 → 必须注明是哪一条

**"缺少依据"和"不满足"是两回事**，绝不能混。简历没写学历 → 待定；简历写了专科而门槛要求本科 → 淘汰。

**待定不等于不用打分**：待定候选人同样要打分（见第三节），只是在分数前标注"条件性得分"。

## 三、打分维度（总分 100）

**通过和待定的候选人都要打分**，只有"淘汰"不打分。待定候选人标注"条件性得分"。

| # | 维度 | 权重 | 看什么 |
|---|---|---|---|
| 1 | 岗位硬技能匹配 | 25 | JD 明确要求的专业技能、工具、证书、专业背景 |
| 2 | 相关经历匹配 | 25 | 实习/项目经历与岗位职能、行业、任务的对口度；平台与角色含金量；**学生工作经历在此项加分** |
| 3 | 成果与业绩证据 | 20 | 是否量化；个人贡献是否可辨识（"主导" vs "参与"） |
| 4 | 成长性与学习力 | 15 | 时间线是否递进、能力是否进阶、自学/证书/竞赛/复盘 |
| 5 | 投入度与稳定性 | 15 | 经历的连续性、有无长期坚持的证据、求职动机与岗位是否匹配。**可实习时长属于平台字段，不在本维度判断** |

## 四、打分锚点

每个维度都按下面 5 档打分。**打分时必须对照锚点，并在结果里写一句依据。**

| 档位 | 占权重比例 | 通用标准 |
|---|---|---|
| 精通 | 85-100% | 该维度要求全部有明确证据，且有对应产出 |
| 熟练 | 65-84% | 大部分具备，个别为弱项 |
| 掌握 | 45-64% | 具备部分，缺 1 项关键内容 |
| 了解 | 25-44% | 仅有课程/自学接触，无实操证据 |
| 未体现 | 0-24% | 完全不对口，或简历中未体现 |

各维度具体化：

**维度 1 岗位硬技能匹配（25 分）**

| 分档 | 标准 |
|---|---|
| 21-25 | JD 要求的全部关键技能都有明确证据，且有对应产出 |
| 16-20 | 大部分关键技能具备，个别为弱项 |
| 11-15 | 具备部分技能，缺 1 项关键技能 |
| 6-10 | 仅有课程/自学接触，无实操证据 |
| 0-5 | 简历中看不到任何相关线索（**这是给低分，不等于判定候选人不会**，必须同时列入面试验证清单） |

**维度 2 相关经历匹配（25 分）**

| 分档 | 标准 |
|---|---|
| 21-25 | 有直接对口的实习经历，且职责与 JD 高度重合 |
| 16-20 | 有相关领域的实习/项目经历，部分职责可迁移 |
| 11-15 | 有泛相关经历（如社团、课程项目），需要一定培养 |
| 6-10 | 经历与岗位关联弱，但从学生工作/项目中能看到可迁移能力 |
| 0-5 | 无任何相关经历 |

**维度 3 成果与业绩证据（20 分）**

| 分档 | 标准 |
|---|---|
| 17-20 | 多处量化成果，个人贡献清晰可辨识（"主导""独立完成"+数据） |
| 13-16 | 有量化成果，但个人贡献需要推断 |
| 9-12 | 以描述性语言为主，少量数据支撑 |
| 5-8 | 全是职责描述，无任何数据 |
| 0-4 | 只有职位名称和公司名，无内容 |

**维度 4 成长性与学习力（15 分）**

| 分档 | 标准 |
|---|---|
| 13-15 | 经历呈明显递进（职责变重、领域变深），有持续学习证据 |
| 10-12 | 有递进趋势，学习证据一般 |
| 7-9 | 经历平铺，无明显递进；有零散学习证据 |
| 4-6 | 经历之间无关联，看不出成长路径 |
| 0-3 | 信息不足以判断 |

**维度 5 投入度与稳定性（15 分）**

| 分档 | 标准 |
|---|---|
| 13-15 | 经历连续稳定、有长期坚持的证据（同一组织连续任职 1 年以上）、求职动机与岗位高度契合 |
| 10-12 | 经历基本连续，动机清晰 |
| 7-9 | 存在需要确认的空档或跳换，或动机表达模糊 |
| 4-6 | 经历有明显空档或连续短期跳换 |
| 0-3 | 严重不稳定 |

> 注意两点：
> 1. **学生时代的经历周期本来就短**，实习 2-3 个月是常态。判断"稳定性"时看是否**连续短期跳换**，不要把正常的学期制实习当成跳槽。
> 2. **可实习时长不参与本维度打分**，那是招聘平台字段，简历里没有是正常的。

### 关于"简历未体现"的措辞纪律

打分时遇到"简历里没写"，**只描述事实，不下能力结论**：

- ✅ 正确："简历中未提及 Excel 的具体使用场景，建议面试确认"
- ❌ 错误："不具备 Excel 能力"
- ❌ 错误："Excel 能力不足，扣分"

差异在于：前者是待验证项，后者是已经在没有证据的情况下给人定了性。报告里出现后者，就等于把"不擅长写简历"误判成了"能力不足"。

## 五、不占分的两类内容：软性素质与技能水平

### 5.1 软性素质

简历里的"性格开朗、有责任心、学习能力强"是**自述**，不是证据，不参与打分。

处理方式：

1. 用行为代理指标找间接证据，打标签：**强证据 / 间接证据 / 未体现**
2. 每项生成一个面试验证问题

| 软性特质 | 简历里的可观察信号 | 面试验证问题示例 |
|---|---|---|
| 进取心 / 驱动力 | 主动发起过项目、从 0 到 1 的经历、持续自学与进阶证书、跨专业自学 | "简历里提到自学了 X，当时是什么推动你去学的？学到什么程度？" |
| 抗压 / 执行力 | 多任务并行（实习+社团+竞赛）、明确时间紧的任务、长期坚持的经历 | "那段同时兼顾实习和社团的时期，你是怎么安排时间的？有没有顾不过来的时候？" |
| 沟通协作 | 跨部门/跨组织协作、组织活动、对接外部合作方 | "讲一次你需要说服别人配合你的经历，对方一开始为什么不愿意？" |
| 责任心 | 有始有终的项目、被委派关键角色的经历 | "你负责的事情里，有没有出过差错？后来怎么处理的？" |
| 学习力 | 快速上手新工具/新领域、复盘与迭代的痕迹 | "有没有过短时间要学会一个全新工具的经历？你怎么学的？" |

### 5.2 技能水平类（如"Excel 熟练""PPT 精美"）

这类技能**不设门槛、不单独计分**，只做两件事：

1. 在维度 1 里按简历中的**证据强弱**加分（有项目/成果 > 只列在技能栏 > 完全没提）
2. 简历里没有证据时，生成一条面试验证问题列进报告

| 待验证技能 | 面试验证问题示例 |
|---|---|
| Excel / 数据处理 | "简历里提到处理过数据，能说说具体用了哪些函数或功能吗？举个例子。" |
| PPT / 汇报 | "有没有做过完整的汇报材料？受众是谁？大概多少页？" |
| 文案 / 写作 | "能发我看一份你写过的文案或报告吗？" |
| SQL / Python | "有没有用 SQL 或 Python 解决过实际问题？当时是什么场景？" |

**判断标准要在面试时当场验证**，例如让学生现场描述一个用数据透视表或 VLOOKUP 的真实场景，比看技能栏写了什么可靠得多。

## 六、评级

| 总分 | 评级 | 建议 |
|---|---|---|
| ≥85 | 高度匹配 | 优先约面 |
| 70-84 | 基本匹配 | 约面 |
| 60-69 | 勉强匹配 | 待定，视候选池情况 |
| <60 | 不匹配 | 不建议约面 |

**评级只用于排序参考，不能替代 HR 判断。** 输出中必须保留合规声明。
